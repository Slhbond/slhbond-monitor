# Slhbond-Monitor v1.20

轻量级 Linux 系统监控面板，纯 C 实现，只依赖 libc 与 pthreads。
装完即用：实时面板 + 每秒历史回溯 + 超限告警 + 命令留痕 + 一键自更新。

---

## 亮点

- **实时面板**：系统信息、CPU（逐核）、GPU、网络波形、NPU、多块磁盘，一屏看完
- **每秒溯源**：每秒压一条定长记录到本地，可拖时间轴回看任意一刻，24 小时约 3.6 MB
- **超限自动记录**：6 项指标（CPU / 内存 / CPU 温度 / GPU / NPU / 硬盘温度）阈值可调，
  连续超限自动记下时间与峰值，面板上还能看到每个指标距离记录还差几秒
- **命令留痕**：记录用户执行的命令，**删除类操作（rm / rmdir / unlink / shred / truncate）
  用红色单独标出并提取目标路径**
- **开关机 + 登录记录**：用内核 `boot_id` 判定整机真的重启过，服务自身重启不会冒充「关机」
- **一键自更新**：面板上有「检查版本」按钮，每天 00:00 也会自动查；发现新版点一下即自动下载校验安装

---

## 新增功能

### 命令执行记录
- 每秒 4 次扫描 `/proc`，记录新进程的完整命令行、用户、PID、父进程
- 同时增量读取 `~/.bash_history` / `~/.zsh_history`，补上存活不足一秒的交互式命令
- 识别删除类操作，包括 `sh -c "rm -rf ..."` 这种包装形式，记录里带上目标路径
- 面板上有「只看删除」开关，「事件」按钮上挂删除次数角标

### 告警实时状态
每个阈值输入框下面多了一行实时状态：

```
CPU 使用率 %  = 90     当前 5.9%
CPU 温度 °C   = 80     当前 43.1°C
NPU 负载 %    = 90     未检测到
```

超限时变成 `已超限 8 / 10 秒`，达到时长后变 `已记录中 12 秒` ——
不用再猜「是没触发还是漏记了」。

### 检查版本与自更新
- 版本号下方新增「检查版本」按钮，手动查一次
- 每天 `00:00` 自动检查一次，另外每 30 分钟一次（`update_daily_hour` 可改）
- 发现新版本后出现蓝色「更新可用」，点它即：下载 → SHA-256 校验 → 解包暂存 →
  root 定时器在 5 分钟内自动安装并重启
- HTTPS 下载委托系统自带的 `curl` / `wget`；**SHA-256 由项目自己实现，不链接 OpenSSL**

### 整机开关机记录
- 用 `/proc/sys/kernel/random/boot_id` 判断内核是否真的重启过
- 开机时间由 `/proc/uptime` 反推，是真实的内核启动时刻
- 断电或强制重启会标明「关机时刻无法确定」，不编造时间
- 服务自身的启停单独记录，默认隐藏，不会冒充整机关机

## 修复

- **告警判定改为按真实经过的秒数**，而不是采样条数 —— 采样重复或漏采不再让「持续 10 秒」失真；
  两次采样间隔超过 5 秒按中断处理，不会把没测到的空档算成持续超限
- **峰值边涨边落盘**（最多每 5 秒一次），服务中途重启也不会把峰值记小
- **正在进行的超限在服务停止时记为「服务停止而中断」**，不再无声消失
- **修复运行期间的登录不记录**：登录库扫描原先只在启动时跑一次，现在每 10 秒补齐
- **修复服务重启被误记为整机关机**（这正是旧版「关机」记录密集出现的原因）
- **修复一处空指针写导致的崩溃**：外部命令执行在「只要退出码、不要输出」时会被写空指针
- **修复更新定时器因单元引用错误而从未启动**
- **修复等待循环把提前唤醒当成到点**，导致每日检查可能提前触发
- **修复命令日志的写放大**：原先每来一个新进程就重写整份日志，改为追加写 + 超限压缩
- **修复格式升级时误删登录记录**：现在只丢弃语义错误的那两行，保留登录历史

| 场景 | CPU（单核） | 占整机 | 常驻内存 |
| --- | --- | --- | --- |
| 空闲 | 3.9% | **0.98%** | 3.1 MB |
| 12 客户端并发压测 | 4.2% | **1.05%** | 3.5 MB |

- 可执行文件 744 KB，发布包 2.4 MB，安装后 9.2 MB
- 线程数固定 9 个，长时间运行不增长

- 命令记录最多 500 条（约 0.4 MB），日志追加写、涨到约 1 MB 压缩一次

## 安装

```bash
tar xzf slhbond-monitor-1.20.tar.gz
cd slhbond-monitor-1.20
sudo ./deploy.sh          # 菜单：1 部署 / 2 卸载 / 3 退出
```

装完访问 `http://<设备IP>:8090/`，自动开机自启。

**依赖**：`gcc`、`make`（本机编译）、`systemd`；`curl` 或 `wget`（可选，仅自更新需要 https）。

**支持**：x86_64 与 aarch64（arm64）通用；systemd / OpenRC 均可。

## 已知限制

- **NPU**：需要内核启用 `CONFIG_ROCKCHIP_RKNPU`；没有驱动时该项显示「未检测到」，不参与告警判断
- **shell 历史**：`/root/.bash_history` 通常是 `0600 root:root`，而服务刻意不以 root 运行，
  所以读不到它。面板会如实说明，不会假装历史可用。命令记录仍覆盖存活 ≥0.25 秒的进程；
  需要完整记录 root 的交互式命令请接入 `auditd`
- **命令记录抓不到存活不足约 0.25 秒的进程**
- **硬盘温度**依赖 `smartctl`；部分 USB 硬盘盒不支持 SMART，此时显示为不可用
